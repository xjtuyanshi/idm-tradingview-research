## 3. 对账过程中实证确定的四条微语义（已写回契约/实现）

这四条都是文档推不出来、只能靠真数据钉死的：

1. **HTF `[1]` 映射按开盘时间归属**（审计未知项 I-2 关闭）：`request.security(tf, expr[1], lookahead_on)` 把 3m K 归入**包含其开盘时刻**的 HTF K，再取前一根。跨越 10m 边界的 3m K（每 30 分钟 2 根，占 20%）暴露了口径差——修正前恰好 301/1508 根 ctx 不一致，修正后 0。等价表述：取最后一根 `HTF收盘 ≤ 3m开盘` 的 K。
2. **`ta.ema` 用 SMA 播种**：前 `length−1` 根为 na，第 `length` 根等于前 length 值的 SMA。首值播种的实现会产生按长度衰减的假瞬态（ema12 约 96 根）；SMA 播种后 0 差异。
3. **`ta.pivotlow/pivothigh` 平局规则：左侧允许平局、右侧严格**。平底/平顶取最近那根为 pivot。两个反向判例（7/16 17:xx 的 7536.4 支撑、7/17 晚的 7483.8 压力）唯一地确定了该规则；修正后 S1/R1 从 42 根差归零。
4. **CAPITALCOM 日线不是均匀 24 小时**：周日重开 K 只有 23 小时（周日 22:00→周一 21:00 UTC）。固定 +24h 收盘约定会让新会话第一小时用到过期日线锚，产生幽灵信号；改为"下一根开盘时间封顶"后归零。

## 4. 剩余差异的定位：亚皮米级浮点边界（黑盒 parity 的诚实底线）

主采样本 3 个 replica 多余信号、复采样本 2 个（重叠），加 ≤7 根 blocker 位差，每一例都解剖到了**判定margin ≤ 2×10⁻¹²** 的比较：

- 例一（7/20 22:27 SELL PULLBACK C）：判据 `close < low[1] − triggerBuffer` 即 `7437.4 < 7437.6 − 0.2`；IEEE 双精度下右边 = 7437.4000000000005，两边差 5×10⁻¹³。
- 例二（7/21 09:06 SELL REJECTION C）：判据 `close < R1 − 0.2` 即 `7486.9 < 7487.1 − 0.2`，同类 1×10⁻¹² margin。
- 例三（7/21 21:36 LONG PULLBACK B）：**Pine 自己的两个主机在这根 bar 上互相矛盾**——3m 主机（实时逐 tick 确认路径）未记录该信号，10m relay 主机（独立 request 上下文、加载时历史重算）记录了同 id 信号（这就是 §2 中 211/212 的唯一例外）。replica 与 10m 主机一致。复采（纯历史重算）后该信号在 3m 主机侧消失确认了实时/历史分叉的存在。

结论：在导出字符串保留完整 double 往返精度、且两侧使用相同运算次序的前提下，这些 bar 的判定取决于 Pine 运行时内部的表达式编译/舍入细节，从黑盒外不可进一步复刻——**Pine 两主机内部都无法在这类 bar 上自洽**。当前守护测试将其钉死为"多余信号 ≤4、Pine 侧零遗漏"的地板，后续任何回归都会被测出。

对产品的实际含义（写入使用注意）：贴着 `触碰容差/突破缓冲` 边界一个 tick 内的信号本质上是抛硬币，实时看到的信号在重载后可能消失（反之亦然）。这与 docs 的 Reload/Replay 验收条款相关，属于冻结版的固有行为，非本次引入。
