# IDM 系统设计（v15.1，2026-07-28）

> 这份文档回答一个问题：**这套东西到底在赌什么，凭什么，哪些还没被验证。**
> 它取代此前所有系统说明。凡是标【已验证】的都能复现；标【假设】的就是还没被测过，
> 界面上不得暗示它有效，也不得接推送。

---

## 〇、一句话

**在一个具名位上，等一个"这个位守没守住"的判据，然后朝下一个具名位下注。**

具名位是**位置**，EMA/背离事件只是**判据**。没有位 = 不下注。
这一句是 2026-07-28 与 Saty 当日实盘逐条对账后重写的，它取代了 v14 的
"EMA 事件即信号、位只是目标"的结构——**那个结构的因果是反的，也是账本亏损的根源。**

## 一、为什么必须重写：v14 的三份尸检报告

v14 在 CAPITALCOM:SPX500 上前向累计 **696 笔 / 32% / −45.1R**
（RTH 186 笔 38% −15.9R；夜盘 510 笔 30% −29.2R；
Recovery 354 笔 30% **−41.6R**；Vomy 342 笔 35% −3.5R）。

三条已验证的死因：

| # | 结论 | 证据 |
|---|---|---|
| 1 | **入场时点不带方向信息** | 纯括号单（保护位 vs T1 谁先到，与出场规则无关）53.4%，几何零假设 S/(S+T)=56.8%，z=−1.68。60 个格子的 z 中位 −1.33，**没有一个越过 +1.96** |
| 2 | **收紧门槛只减少笔数，不改善每笔期望** | 8 个变体把频率压掉 83%，均 R 始终在 −0.184~−0.045 |
| 3 | **止损贴脸被噪音+点差两头吃** | Recovery 保护位中位 0.065 ATR、33% 死在保护位；Vomy 的 fin 保护位 0.151 ATR、只有 5% 被扫。0.6 点点差占 6.25 点风险的 9.6% |

第 1、2 条合起来是最刺眼的：**如果收紧任何门槛都不改善每笔期望，那问题就不在"要不要下注"，
而在"这一注下在什么位置"。** 我此前一直在调前者。

这同时解释了尸检第 2 条：调幅度救不了符号。

## 二、三层结构

```
┌─ 第 0 层  状态（区间 / 趋势）        ← v15.1 新增，决定【用哪套规则】
├─ 第 1 层  地图（具名位）             ← 已验证，是位置与目标的唯一来源
├─ 第 2 层  判据（三个 setup）         ← 只回答"这个位守没守住"
└─ 第 3 层  执行（风险/分批/账本）     ← 目标永远是具名位，不是 R 倍数
```

### 第 0 层：状态

| | 判定 | 允许的动作 |
|---|---|---|
| **区间** | 价格在 trigger box 内（\|ratio\| ≤ 0.236）**或** 五条 EMA 未排列 | 只做**边缘拒绝**与**背离**，方向必须朝盒内。**交叉类禁用** |
| **趋势** | 五线排列 **且** 已在 box 外 | 三类 setup 全开 |

> ⚠ 这**不是**我此前否掉的那种 regime 过滤器。`REGIME_MONTHLY_BOX_2026-07-25.md`
> 否掉的是「箱内胜率更低，所以少做」——那是对**同一套规则**开关（20 年样本否定，
> 会误伤 43% 的交易日）。这里是**换规则**：区间态改用边缘拒绝。两者是不同的命题，
> 前者被否不蕴含后者被否。**但后者也还没被验证。**

### 第 1 层：地图（唯一已充分验证的一层）

ATR 梯的构造已**逐位对到分**，与官方 Saty ATR Levels 在用户自己的
CAPITALCOM:SPX500 上一致（锚 7417.50 / ATR 88.48 / call 7438.38 / put 7396.62 /
+1ATR 7505.98，另一日 7578.80 / 91.97 复验）。

具名位全集 = ATR 梯（±0.236/0.382/0.5/0.618/0.786/1.0/1.272/1.618 + PDC 锚）
＋ **夜盘高低 / 盘前高低 / PDH·PDL**（语料统计里他用得最多的三组非 ATR 位）。

**已验证的负面结论，必须一起记住：**
- 名义斐波那契比例**不特殊**。安慰剂梯子（起点 0.20→0.70 平移、固定 0.236 前进）
  给出平滑单调曲线，具名位残差 ≤0.76σ；整条梯子平移后完成率 63.7% vs 真 GG 64.6%。
  **Golden Gate 只是"从任意位置再走 0.236 ATR"的别名。**
- 所以位的价值**不在比例本身**，在于「它是一条大家都在看的线，价格到那儿会有反应」，
  以及它给了**一个可定义的位置与一个可定义的目标**。这是位置属性，不是预测属性。
- 「ATR 已走 >70% 就别进场」方向是**反的**（六个时段全部同号）。不实现。

### 第 2 层：判据（对应用户自己描述的三步）

| | 用户原话 | 实现 |
|---|---|---|
| S1 翻转 | 「袋子变红了就往下走」 | 五线排列刚形成 + 收盘站到 EMA8 外侧。**区间态禁用** |
| S2 拒绝 | 「反反复复下不去」 | 同一具名位独立触及 ≥N 次（进 ±0.03 ATR 记一次，离开 ≥0.05 ATR 才能记下一次）后从该位离开 |
| S3 背离 | 「Saty Oscillator 底背离」 | 价格创 N 根新极值、Phase 不创。Phase 用**已修正**公式 `(close−EMA21)/(3.0×ATR14)×100` 再 EMA(3) |

> Saty 07-26 #notes 开篇即是「10m **divergence at support** to complete the 10m
> mean reversion if lows hold」——S3 与"具名位"在他那里本来就是绑在一起的。

### 第 2.5 层：位置闸门（v15 的核心，五条子闸门）

任一不过 → **不入场**，在图上打灰点并写明是哪条挡的。

| | 闸门 | 默认 | 来源 |
|---|---|---|---|
| ① | 入场价离 EMA13 ≤ | 0.10 ATR | 反追高的直接代理 |
| ② | 信号 K 振幅 ≤ | 0.20 ATR | K 越大，收盘入场越是在这根 K 的极端 |
| ③ | 前 3 根顺向净位移 ≤ | 0.35 ATR | 「刚急拉完再顺着做 = 追」 |
| ④ | Phase 顺向极端否决 | ±61.8 | 他的原话「3m extreme here, 10m has room」 |
| ⑤ | **离最近具名位 ≤** | **0.10 ATR** | **本文第 1.1 节；这条最硬** |

**灰点是 v15 最该看的东西：它让你看见系统"忍住没追"的时刻。**

### 第 3 层：执行

- 最小风险距离 **0.12 ATR**（尸检第 3 条定的，不是拍脑袋），保护位再加 **0.03 ATR** 缓冲
- 目标 = **下一个具名位 / 再下一个具名位**，永不使用 R 倍数
  （他的语料里 **0 次**出现"目标 2R"）
- 分批 50% / 25% / runner，对应他的 "scale out + leave runners"
- 出场用**另一条线**（EMA21/34/48 可选，**EMA13 不可选**）+ 最小持仓 3 根
- 偏向（日线 21）**只显示与分组，从不阻止任何一笔入场**
  ——用户明确否掉硬闸门：「日内交易不可能一直都是单边下跌的」

## 三、账本：这套东西怎么被证伪

图上常驻账本，8 个分组：全部 / RTH / 夜盘 / 顺偏向 / 逆偏向 / S1 / S2 / S3。

**正确的零假设是几何零假设 S/(S+T)，不是 50%。** 止损近、目标远本身不产生期望值——
必须跑赢几何基准。v14 就是死在这条上（53.4% vs 56.8%）。

**在均 R 转正、且相对几何零假设的 z 越过 +1.96 之前，一条推送都不发。**

## 五、Pine 做不了、可能需要 AI 的部分

用户的判断是对的：有些东西纯 coding 不好实现。具体是这几处，按"多需要判断"排序：

| 事项 | 为什么 Pine 难 | 可能的形态 |
|---|---|---|
| **"这个位是不是真的关键"** | 具名位有十几条，但他每天只点名 2–3 条。哪几条今天算数，取决于盘前结构、隔夜事件、相对大盘强弱 | 盘前用 AI 读一遍夜盘/盘前结构 + 事件日历，输出**今日只看这 3 条位** |
| **"反反复复下不去"的次数** | 2 次还是 3 次是玄的；真正的判据是"每次测试的力度在衰减" | 让 AI 看一段 K 线序列给出"衰竭/未衰竭" |
| **双周期 Phase 配对读数** | 「3m extreme, 10m has room」是一句判断，不是阈值 | Pine 出两个数，AI 出一句话 |
| **双分支剧本文案** | 他每天写的就是这个，而且**没有信号的时候剧本本身就是价值** | 盘前自动生成 IF/THEN 两支，用具名位 |
| **状态定性** | "big events on the horizon → smaller range" 需要读事件日历 | 同上 |

**呈现形态的建议**：先不做网站/App。这几件事的共同点是**盘前一次、盘中偶尔一次**，
不需要实时。最低成本是每天开盘前生成一份**剧本卡**（两分支 + 今日只看这 3 条位 +
预算表），TradingView 那边只负责画位、发判据、记账本。等剧本卡跑通了、账本转正了，
再谈要不要做成 App。
