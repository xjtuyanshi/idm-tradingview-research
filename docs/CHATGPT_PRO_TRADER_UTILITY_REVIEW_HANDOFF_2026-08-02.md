# ChatGPT Pro 独立 Trader Utility Review｜2026-08-02

## 任务性质

你是独立的 SPX 日内交易者 reviewer，不是本系统的作者。请只根据每根 K 线当时已经闭合且可见的信息判断，不得用后续走势倒推信号“应该成立”。本轮只做审查与最小收敛方案，不编写新指标、不声称盈利能力，也不把图形回放说成真实成交。

## 背景与目标

现有系统经历多轮迭代，图上曾同时出现 10m 趋势/位置、3m timing、P6 ATR 位置反应、R4 沿云续势，以及 `趋势多/趋势空/多头退/空头退/冲突/重置/观察/确认` 等多套文字。用户的直观反馈是：标签多、语义不清、偶尔出现没有可见开仓来源的“关多/关空”式管理信号，而且灰色文字在黑色背景上看不清。

本轮目标是回答一个窄问题：如果你在盘中第一次看到这些信号，哪些真的能改变行动，哪些只是审计噪声？最终主图应收敛为不依赖说明书也能理解的最小信号语言。

## 数据边界（必须原样保留）

- 旧复杂 P6/R4/R5.1：真实 TradingView 3m export，11,815 根，2026-06-28 18:00 至 2026-07-31 16:57 ET，覆盖 30 个 ET 日期。它含 3m OHLC 和历史信号列，但不是 90 天数据。
- 当前最小 R3：真实 native 10m export 337 根，仅 2026-07-29 06:00 至 2026-07-31 14:00 ET；配套 3m timing event ledger 也只覆盖这约 2.5 天。
- 目前没有当前 R3 的 30/90 天 native-10m parity export。因此不得把旧 33d 结果归因给当前 R3，也不得给当前 R3 报 30/90 天胜率。
- CSV 不含真实成交、点差、滑点、期权价格、手续费或执行延迟。

## 需要审查的信号族

1. 旧 R4/R5.1：`趋势多/趋势空/多头退/空头退/方向冲突/数据重置`。用户也会把退场类信号称为 `关多/关空`。
2. 旧 P6 ATR 位置反应：`近支撑/近阻力 → 支撑守住/阻力压回 → 反弹确认/回落确认 → 失效/到期`。
3. 当前 R3 10m：`观多/观空/主多/主空`。
4. 当前 R3 3m：`多入/空入/失/达`。
5. 位置反转脚本及 MTF 位置反应脚本中可能出现的 `支撑观察/阻力观察/D20到达` 等文字，仅评估呈现与语义，不把 synthetic contract 当市场表现。

## 无后视镜审查协议

对每个代表案例，必须记录：

- 信号 K 的开盘时间与信号真正可知时间；
- 当时可见的方向、关键位置、触发、失效、目标；
- 下一根 K 开盘作为最早可执行锚点；
- 到计划终止前的 MFE/MAE；
- 是否重复、冲突、延迟、缺少 plan owner，或出现“只有退场、没有可见入场”；
- 若同一根 K 同时可能触发目标和止损，标为路径不明，不擅自排序；
- 至少列出：3 个有用案例、3 个坏案例、2 个漏掉的大机会、2 个标签语义/生命周期冲突案例。若数据不足，明确写不足，不凑数。

## 必答问题

1. 以手机看盘的 trader 视角，哪几个信号可以在 5 秒内改变行动？
2. `多头退/空头退` 或 `关多/关空` 是否对没有明确持有对应 plan 的人有任何实盘意义？如果保留，必须满足什么 owner/lifecycle 条件？
3. 10m `观多/观空` 是否适合保留历史主图？还是只适合当前卡片/alert？
4. P6 的“接近、反应、确认”哪一级才可成为主图事件？哪一级只能是预警？
5. 当前 R3 的 10m/3m 分工是否清楚？主图最小词汇应如何命名？
6. 灰色/银色文字哪些属于关键行动，必须提升为纯白或高饱和；哪些只应留在 Data Window？
7. 给出明确的 `保留 / 改名 / 合并 / 默认隐藏 / 删除` 表。不要只说“可以优化”。

## 交付物

- 一页式 trader verdict，开头直接写 `可用 / 仅部分可用 / 不可用`。
- 逐案例无后视镜 ledger。
- 信号保留矩阵。
- 一个最小主图合同，最多包含：一个 10m plan 状态、一个 3m entry、一个失效、一个目标；若你认为还需第五类，必须解释为何不能放卡片。
- 当前证据不足的项目清单，以及取得何种新 export 才能继续验证。

## 禁止事项

- 不得修改代码、创建订单、alert、策略回测、Git commit/push/PR 或部署。
- 不得把 33d 旧系统结果说成当前 R3 结果。
- 不得声称真实盈利、胜率、edge 或生产验证。
- 不得用未来 K 线给信号补理由。
- 不得因为某个案例最后上涨/下跌，就跳过当时的触发、保护与目标定义。

## 验收标准

报告必须让另一个 trader 不读源码也能回答：图上每个保留词是什么意思、何时行动、何时不行动、持有什么 plan 才能管理，以及为何被删的词没有增量价值。
