# IDM v11 激进版：从零重做规格

> 历史规格警告：这是实现前的冻结设计稿，不是当前源码的权威参数表。已知漂移包括这里写的最大风险 `1.25 ATR`，而冻结 Pine 实际为 `1.30 ATR`。发生冲突时以 `release-manifest.json`、冻结 Pine 和 `docs/STATUS.md` 为准；下一位开发者应先完成 Pine/oracle 配置统一，而不是照此文档直接调参。

状态：冻结为 v11 第一版实现契约。它不继承 v10 的 episode 状态机。

## 1. 这次为什么重做

v10.1 的失败不是“标签没画出来”，而是正式信号漏斗把机会筛成了零：49 个观察 episode 只有 8 次完整触发，最终没有一个正式 SignalEvent。截图中的 2026-07-21 早盘又暴露了同一个问题：10 分钟趋势和 3 分钟节奏都持续向上，系统却一直要求价格回到一个已经过时的位置。

v11 不再修补这条链路。每根确认的 3 分钟 K 线都直接检查四类交易 Setup；完整的价格条件可以在当根收盘形成正式信号。

## 2. 唯一信号时间线

```text
已确认的 10m 背景
        ↓
每根确认的 3m K 检查四类 Setup
        ↓
候选包含方向、级别、Entry、Stop、T1、T2、原因
        ↓
确定性同 bar 路由和去重
        ↓
BUY / SELL
        ↓
HOLD / PROTECT / EXIT
```

- 3 分钟是唯一正式事件源。
- 10 分钟图只显示同一个 3 分钟事件，不重新计算另一套信号。
- 10 分钟只使用已确认值，禁止前视。
- VIX、NDX 只允许作为同步时的小型背景证据，不能阻挡核心信号。

## 3. 四类 Setup

### Trend Ignition（趋势启动）

EMA 5/12 翻转或价格重新穿越 3m 34/50 Cloud，同时突破此前四根结构并由强方向 K 收盘确认。用于抓住从底座启动的第一段行情，不能要求先出现隐藏的观察 episode。

### Pullback Continuation（回踩延续）

趋势背景兼容，价格触及 3m 5/12、3m 34/50、确认的 10m Cloud 或有效支撑/压力后重新收回。强拒绝 K 可以同 bar 确认；普通拒绝等待下一根突破拒绝 K。

### Compression / Structure Breakout（压缩或结构突破）

收盘突破此前八根箱体边缘，方向 K 足够明确，3m 5/12 已同向或当根翻转。Phase 压缩可以加分，但不是硬门槛。

### Level Rejection（关键位拒绝）

价格扫过支撑/压力后收回，或多次测试但未收盘破位，随后突破确认 K。该 Setup 负责避免“在支撑附近追空、在压力附近追多”。

## 4. A / B / C

A/B/C 表示规则完整度和建议风险档位，不是假装成历史胜率：

- A：10m 主趋势与节奏同向、3m Setup 完整、位置不过度延伸、T1 至少 1R，另有 Phase/关键位共振。
- B：3m Setup 完整，10m 同向但节奏过渡，或 10m 中性而 3m 结构清楚，T1 至少 0.75R。
- C：逆 10m 的关键位拒绝或强 3m 翻转试仓，T1 至少 0.55R。

默认风险参考：A 1.00x、B 0.65x、C 0.35x。它不是历史 Confidence。

## 5. 交易几何和管理

正式 SignalEvent 当刻冻结：

- Entry：信号 K 收盘确认价；策略成交假设必须另行明确。
- Stop：Setup 的结构失效点，外加 ATR 缓冲。
- T1：最近真实障碍或 1R，取较近者。
- T2：第二真实障碍或 2R，取较近者。

只保留三个硬安全限制：Stop 方向正确、风险不超过 1.25 ATR、T1 空间至少 0.55R。

- HOLD：计划未失效且 3m 节奏/结构仍完整。
- PROTECT：T1 到达，或关键压力/支撑配合确认背离及节奏损伤；默认提示止盈 60%，余仓保护。
- EXIT：Stop、T2、正式反向信号，或关键位拒绝并确认破坏 3m 节奏。
- 禁止只因固定 K 数到期就退出；时间只能与“走势没走开且节奏失败”共同构成退出。

## 6. 图表必须一眼能看懂

默认只画：

- 3m 5/12 执行 Cloud；
- 已确认 10m 34/50 背景 Cloud；
- 最近 S1/R1；
- 当前 Entry/Stop/T1/T2；
- 历史 BUY/SELL 小标；
- 最新事件一张详细标签。

面板固定四行：现在、10m、下一步、计划。空仓时必须显示明确的 BUY 与 SELL 触发条件，禁止只写“偏多观察”“等待位置”。

手机 Alert 使用自然中文；JSON 仅作为单独 webhook 开关。所有标签、提醒、策略订单必须由同一个 event id 产生。

## 7. 2026-07-21 早盘验收

在用户截图这类单边上涨上午：

1. 第一段有效启动或结构突破至少形成一次 BUY；
2. 首个有效 Cloud 回踩重新站稳时，空仓允许 BUY；
3. 入场后整段趋势显示 HOLD，而不是重新退回“等待位置”；
4. 到达近端压力后显示 HOLD/PROTECT，不在压力前追多；
5. 每一根未交易 K 都必须给出具体 WAIT/BLOCKED 原因；
6. 3m/10m 的 event id、时间、Entry、Stop、T1、T2 一致；
7. Reload 和 Bar Replay 后事件不移动、不消失。
