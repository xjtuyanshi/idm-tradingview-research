# TradingView 使用与验证

## 导入

1. 打开 TradingView 的 Pine Editor。
2. 新建空白策略脚本。
3. 复制仓库根目录的 `intraday_decision_map_v11_aggressive_clean.pine` 全部内容。
4. 保存后选择 `Add to chart`。
5. 确认脚本标题为 `IDM v11 Aggressive Clean`，版本常量为 `11.0.0-clean`。

GitHub 代码不会自动进入你的 TradingView 私人脚本；仍需上述复制步骤。

## 推荐布局

建议单独建立一个布局，名称：

```text
IDM Research｜SPX 10m + 3m
```

- 左侧大窗：SPX500 10m，负责背景和持仓管理。
- 右上：同一标的 3m，负责确认后的入场事件。
- 可选右下：只在同步的现金交易时段观察 VIX；v11 本身尚未把 VIX 纳入模型。
- 不需要再堆 MACD、多个震荡器和重复 EMA 投票。

两个 SPX 窗都加载完全相同的 v11 源码和参数。3m 是唯一 SignalEvent 主机；10m 只是同源只读视图。

## 正常看盘设置

- `启用 3分钟策略订单`: 关闭。
- `启用中文动态提醒`: 开启。
- `显示 3分钟 5/12 Cloud`: 开启。
- `显示确认 10分钟 34/50 Cloud`: 开启。
- `显示最近 S1 / R1`: 开启，但注意当前版本还没有把来源名称显示出来。
- `显示 Entry / Stop / T1 / T2`: 开启。
- `保留历史 BUY / SELL`: 开启。
- `显示最新信号说明`: 开启。
- `显示四行面板`: 开启。

## 图上的含义

- 绿色/红色细 Cloud：3m EMA 5/12，表示执行节奏。
- 蓝色/橙色较粗 Cloud：上一根已确认 10m EMA 34/50，表示背景。
- 青色 S1：当前算法挑出的最近支撑。
- 橙色 R1：当前算法挑出的最近压力。
- 黄色 Entry：冻结入场参考。
- 红色 Stop：当前有效失效位。
- 青色 T1 / 蓝色 T2：冻结目标。
- 买A/买B/买C、卖A/卖B/卖C：历史正式 SignalEvent；ABC 是规则档位，不是概率。
- 护/退/反/止/T1/T2：计划管理事件。

Cloud 变绿不等于立刻 BUY；它需要价格在位置上完成拒绝、收回、结构突破或趋势启动。Cloud 变红也不等于立刻 SELL。

## 为什么有时没有信号

面板“下一步”会显示当前结构参考和主要缺失条件。常见原因：

- 尚未收破确认 K；
- 10m 与候选方向冲突；
- Stop 超过 1.30 ATR；
- 最近目标空间小于 0.55R；
- 在支撑附近追空或压力附近追多。

如果 3m 已经持续站在 5/12 上且 10m 方向偏多，系统至少应处于寻找回踩 BUY 或 HOLD LONG 的路线；但现有负期望结果说明“能发信号”仍不等于“应该实盘照单执行”。

## 创建手机提醒

在 3m 图创建一个动态提醒：

1. 点击 `Alert`。
2. Condition 选择本脚本。
3. 选择 `Any alert() function call`。
4. Frequency 选择 `Once Per Bar Close`。
5. 勾选 App 推送。

10m 不要再创建第二个总提醒，否则同一 3m 事件可能收到重复通知。提醒创建后，如果脚本源码或关键参数更新，应删除旧提醒并重新创建；TradingView 的已有提醒通常保存创建时的脚本快照。

手机文案应是自然中文，例如：

```text
IDM v11｜出现做多信号 B｜回踩续涨｜价格 ...｜止损 ...｜目标1 ...
```

如果仍看到 JSON/乱码，说明收到的是旧提醒快照，而不是当前 v11；删除旧提醒并按上述步骤重建。

## Strategy Tester

只在 3m 图临时打开 `启用 3分钟策略订单`。10m 永远不应下单。完成测试后立刻关回去，避免 broker emulator 箭头污染日常图面。

记录版本、标的、时区、日期、手续费、滑点、订单数量和完整报告。必须把独立 Plan 与 T1/T2/runner 退出腿分开统计。

当前保存的结果是负期望，不能据此按 A/B/C 加大真实仓位。
